# 抓阄抽签 (DrawLots)

[![Android CI](https://github.com/et9930/DrawLots/actions/workflows/android.yml/badge.svg)](https://github.com/et9930/DrawLots/actions/workflows/android.yml)
[![License: MIT](https://img.shields.io/badge/License-MIT-yellow.svg)](LICENSE)
[![Android](https://img.shields.io/badge/Android-7.0%2B%20(API%2024)-3DDC84?logo=android&logoColor=white)](https://developer.android.com/)
[![Kotlin](https://img.shields.io/badge/Kotlin-2.4-7F52FF?logo=kotlin&logoColor=white)](https://kotlinlang.org/)

一个用于**抓阄 / 抽签**的安卓 App：签可以是文字，也可以是图片（相册选图或直接拍照），每个签都能设置数量；
抽出的签按顺序排列；可以选「放回」或「不放回」。

Kotlin + Jetpack Compose（Material 3），最低支持 Android 7.0（API 24），目标 API 36。

---

## 1. 功能

### 做签（「签池」页）
| 能力 | 说明 |
| --- | --- |
| 文字签 | 手动输入内容；打开「每行作为一个签」可以一次批量输入多行，每行一个签 |
| 图库图片签 | 调用系统相册选择器（支持一次多选，最多 9 张），每张图片成为一个签 |
| 拍照签 | 调用系统相机拍照，拍完直接作为签存入签池 |
| 数量 | 每个签都能用 `− / +` 调整数量（1 ~ 999），数量越多被抽到的概率越大 |
| 编辑 / 删除 | 可以改文字或图片备注、改数量、删除单个签，也可以一键清空签池 |

### 抽签（「抽签」页）
| 能力 | 说明 |
| --- | --- |
| 放回 / 不放回 | 顶部切换。**不放回**：抽走的签不再参与后面的抽取；**放回**：每次都在完整签池里抽 |
| 一次抽多支 | 「每次抽取 N 支」，不放回模式下会自动按剩余数量收尾 |
| 抽签动画 | 点抽签后先滚动展示约 0.7 秒，再落定结果，并伴随振动反馈 |
| 按顺序排放 | 结果按抽出顺序编号排列（网格），每张卡片左上角是当前位次 |
| 放大查看 | 点任意结果可以放大查看图片/文字，以及抽取方式与时间 |
| 备注 | 弹窗里点「添加备注」就能给**这一条**结果写备注（例如「小明抽到」），边打字边自动保存；结果卡片底部显示备注小条，分享/复制出来的结果文本也带备注 |
| 单独放回 | 在放大弹窗里点「放回这个签」，可以把**任意一个**抽出的签放回池子（不只是最后一个），剩下的结果自动重新编号 |
| 撤销 | 一行四个操作按钮：撤销（放回最后一个）/ 重置 / 分享 / 复制 |
| 重置 | 清空结果，所有签放回池子（数量不变） |
| 导出 | 分享抽签结果（文本）或复制到剪贴板 |
| 进度 | 不放回模式下显示「剩余 x / 总数 y」和进度条；签池里每行显示「已抽 / 剩余」 |

### 其它
- **自动保存**：签池、剩余情况、抽签结果都会本地保存，关掉 App 再打开可以接着抽。
- **零权限**：相册用系统 Photo Picker，拍照用系统相机的 `ACTION_IMAGE_CAPTURE`，所以**不需要申请任何存储或相机权限**。
- **图片本地化**：选中的图片会压缩（最长边 1600px）后复制到 App 私有目录，原图删除或权限过期都不影响使用。
- **深色模式**：跟随系统。

需要 JDK 17+ 和 Android SDK（compileSdk 36 / build-tools 36.0.0）。本机环境已经具备：

```powershell
# 本机 JDK 与 SDK
#   JDK:        <JDK>
#   Android SDK: <Android SDK>   （已写入 local.properties）
```

```powershell
cd .
$env:JAVA_HOME = '<JDK>'
.\gradlew.bat :app:assembleDebug          # 编译 debug 包
.\gradlew.bat :app:testDebugUnitTest      # 跑单元测试
```

产物：

```
app\build\outputs\apk\debug\app-debug.apk        # 调试包（已用 debug 签名，可直接安装）
app\build\outputs\apk\release\app-release.apk    # 未签名正式包（需要自己签名后才能安装）
```

安装到手机（打开 USB 调试后）：

```powershell
adb install -r app\build\outputs\apk\debug\app-debug.apk
```

> `.\.gradle-home`（`GRADLE_USER_HOME`）、Android 用户目录重定向到 `.\.android-home`
> （`ANDROID_USER_HOME`）。在普通机器上不需要这些设置，`gradlew` 会用默认的 `~/.gradle`。

## 4. 抽签规则实现（题目核心）

`DrawSession` 不依赖任何 Android API，方便测试。核心思路：**签池里每种签有 `quantity` 支，
被抽走的支数记录在一个 `consumed` 计数器里，而不是直接修改数量**，于是「放回 / 不放回」只是两行分支：

- 每种签被抽到的概率与它的**支数成正比**：
  放回模式权重 = `quantity`；不放回模式权重 = `quantity - consumed`（即剩余支数）。
  实现上是「按支数加权随机」：把每个签看成 `权重` 张票，随机取一张票。
- 不放回模式：命中后 `consumed[id] += 1`，剩余为 0 的签不再进入候选池；
- 放回模式：`consumed` 不变，池子永远是满的，可以无限抽；
- **放回上一签**：删掉最后一条结果，如果当初消耗了一支，就把 `consumed` 减回去；
- **重新开始**：清空结果 + `consumed` 清零（所有签放回）；
- 数量被改小时，`consumed` 会自动收敛到新数量（多出来的支数等于被放回）。

结果 `DrawRecord` 里保存了签的**内容快照**（文字/图片路径/种类/抽取方式/时间/序号），
所以之后修改或删除签，历史结果依然能正确显示，也不会因为签池变动而错位。

## 5. 测试

```powershell
$env:JAVA_HOME = '<JDK>'
.\gradlew.bat :app:testDebugUnitTest
```

一共 **40 个用例，全部通过**（27 + 5 + 4 + 3 个纯 JVM 逻辑测试，加 1 个 Robolectric 界面流程测试）。

### 抽签规则（DrawSessionTest，27 个）

- 不放回抽完整个签池：每种签恰好出现「它的数量」次，抽干后 `canDraw()` 为 false；
- 剩余不足时按剩余数量收尾；`plannedDrawCount` 正确；
- 放回模式抽 50 次不会消耗签池；不放回模式抽空的签不会再出现；
- 概率符合数量比：`A=3, B=1` 时统计 8000 次抽取，A 约占 75%（放回 / 不放回各一个用例）；
- 结果顺序与序号（1,2,3…）严格对应抽取顺序，且等于 `DrawSession.results`；
- 撤销放回一支 / 放回模式下撤销只删记录 / 空历史撤销无副作用；
- **放回指定的某一条结果**：只归还它占用的那一支，其他结果和顺序不受影响，放回的签还能再被抽到；
  放回模式下只移除记录（池子本来就是满的）；找不到的记录不做任何改动；
- **备注**：只写进指定的那一条结果（首尾空格会去掉）、可以改成空备注来清除、写不存在的记录无副作用、
  备注能跟着存档一起读回来；
- 重新开始恢复全部支数；减少数量会把多抽的支数放回；增加数量会多出可抽支数；
- 删除签保留历史结果；清空签池清掉签与结果；
- 中途切换放回模式后可以继续抽，已消耗的支数保持；
- 存档 → 读档后「已抽/剩余」完全一致，并能接着抽到签池抽干。

### 存档、导出文本与批量输入（PoolCodecTest / ResultsTextTest / TextLotEntriesTest，12 个）

- JSON 存档往返完全一致（含中文、换行、空图片路径、备注）；
- 备注能存能读；**旧版本（没有 note 字段）的存档读出来是空备注**，不会报错；
- 坏数据 / 空数据安全回退为空签池；
- 导出文本：空结果给提示、备注跟在括号里、编号按当前位次（中间放回一条后不会出现断号）；
- 批量输入：每个非空行一个签、整段文字一个签、空白输入不产生签、首尾空格被去掉。

### 界面流程（DrawLotsUiJourneyTest，1 个）

用 Robolectric 在 JVM 上真的启动 App（不需要模拟器），一条龙验证：
读档（含一条已抽结果和它的备注）→ 头部统计 → 放回/不放回切换 → 签池列表与每条签的数量 →
一行四个操作按钮（撤销/重置/分享/复制）→ 点结果卡片，弹窗显示「第 1 个签 / 备注：小明抽到 / 修改备注」→
「放回这个签」→ 结果清零、剩余回到 3/3 → 抽一次后「重置」→
清空签池（确认框）→ 空签池状态与提示文案。

关于测试环境的三点说明：

- **Robolectric 的 `android-all` jar**：默认会联网下载到 `~/.m2`。如果所在环境不允许写家目录，
  把 `android-all-instrumented-<版本>.jar` 放到项目根目录的 `robolectric-deps/`，
  构建脚本检测到该目录会自动开启离线模式（`robolectric.offline` + `robolectric.dependency.dir`）。
- **只写了一个界面测试方法**：Robolectric 会在同一个 sandbox 里复用 Application / SharedPreferences，
  多个测试方法之间会互相污染，所以端到端流程刻意放在一个方法里跑完。
- **测试里不碰输入框**：Compose 的文本框光标是无限动画，会让 Robolectric 的 idle 检查一直等待，
  只要界面上有一个文本框，之后所有查询都会卡住。因此备注输入框设计成点「添加备注」才出现
  （默认弹窗里没有文本框，界面测试才能继续跑）；打字与保存由真机验证 + DrawSession 的单元测试覆盖。

## 6. 已知取舍

- 图片做签是「一张图一个签」，多选 9 张就会新增 9 个签，需要批量调整数量时逐个改（暂未做多选批量编辑）。
- 签池顺序即添加顺序，暂不支持拖动排序。
- 存档用 SharedPreferences + JSON：签的种类/结果数量在万级以内没问题；再多建议换 Room。
- 退出 App 后私有目录里的图片会一直保留，只有「删除该签 / 清空签池」时才会删掉对应文件。

## 7. 多机联机（房间）

一台手机当**房主**（权威状态），其他人加入同一场抓阄：所有人实时看到同一份签池与结果，抽出的签**自动署名是谁抽的**。

### 怎么用

1. 顶栏点「**联机**」→ 填「我的名称」（默认取设备型号，抽签时会用这个名字署名）。
2. **创建房间**：填房间名、选连接方式（局域网 / 蓝牙）、按需打开两个放权开关（默认都关）→ 出现二维码 + 6 位房间码 + 成员列表。
3. 其他人**加入**：扫二维码 / 在「附近房间」里点选 / 手输房间码（广播被路由器拦时可在面板里补填房主地址与端口）。
4. 房间中顶栏会常驻状态条（房间名 · 房主/成员 · 人数 · 连接状态），点它可以再看二维码/房间码/成员，右侧可以退出。

### 权限模型（默认最小权限）

| 操作 | 房主 | 成员（默认） | 成员（房主放权后） |
| --- | --- | --- | --- |
| 抽签 / 写备注 | ✅ | ✅ | ✅ |
| 撤销 / 放回指定签 | ✅ | ❌ | 打开「允许其他人放回·撤销」后 ✅ |
| 重置（全部放回） | ✅ | ❌ | 永远 ❌ |
| 签池编辑（加签/改数量/删除/清空） | ✅ | ❌ | 打开「允许其他人编辑签池」后 ✅ |
| 切换放回/不放回 | ✅ | ❌ | 永远 ❌（房间共享规则） |

成员即使被放开编辑，也只能加**文字签**：图片文件在房主设备上，v1 不做反向上传。

### 权限与网络

- 单机使用**不需要任何权限**；只有进「联机」才会按需申请：局域网要网络权限（普通权限，安装即授予），扫码要相机权限，蓝牙房间要蓝牙广播/扫描权限（**仅 Android 12+ 提供**，更低版本请用局域网）。
- 蓝牙房间：房主做 BLE 广播，成员按二维码里的服务 UUID 扫描连接。**建议不超过 6 人**（受 GATT 并发连接数限制），图片传输比局域网慢。
- 局域网房间：手机与电脑/其他手机要在同一个 Wi-Fi 或热点下；房主建房期间会保持屏幕常亮以免被系统冻结。
- 图片签按需拉取：成员第一次显示某张图时才向房主取，缓存在 `room-images/`（上限 50MB，自动淘汰）。

### 已知限制

- 房间不跨进程存活：房主退出 App 房间即结束；成员退出/房主结束时会**恢复自己进房前的签池**（结果不会串到自己的签池里）。
- 蓝牙双机对连未在真机上验证（开发环境只有一台手机），只验证了分片逻辑、GATT 服务注册与广播启动、邀请内容；如遇问题请反馈日志。
- 相机扫「活着的」二维码需要第二块屏幕才能自测；相册选二维码与手输房间码都可作为替代。
- 没有做房主转移、增量补帧、公网联机与前台服务。
